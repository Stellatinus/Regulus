After the login the dashboard shows the **notch** at the top and the **dock** at the bottom ([Design system v3](design-system.md)). The notch has the brand, the **n/m Online** pill (servers connected out of all enrolled) which is also the live indicator (green while the stream to the hub flows; **Connecting…** or **Reconnecting…** in the warning colour, for example while the hub restarts; **Hub unreachable, retrying…** in the error colour only when the stream has been down for 60 seconds, `LONG_OUTAGE_MS` in `Shell.tsx`, #435) and the account menu (**Settings**, **Sign out**). The dock has **Dashboard**, **Nodes**, **Services** (`servers.read`; **Installed**, the plugins page, and **Regulus Store**, not built), **Automations** (only while switched on in Settings; a designer whose drafts are kept in the browser and do not run, #476) and, after a divider, **Admin** with the tabs **Accounts** (`users.manage`: accounts and the two-factor policy), **Roles and permissions** (`roles.manage`) and **Recent activity** (`audit.read`). **Settings** (`#/settings/<category>`) has **Account and security** (change password, two-factor, your sessions), **Appearance and language** (theme: System, Light, Dark, dark is the default; language: browser language, English, Italian; both saved in the browser), **Plugins, apps, automations** (three switches kept in the browser, #474), **Network and core**, **Database** and **Metrics and telemetry** (what the hub reads from its configuration file; the dashboard does not edit it yet, #483) and **Mesh updates** (the Updates page, with `core.update`). `#/account` opens Settings on Account and security. The **Dashboard** page is a grid of widgets: **Customize** unlocks dragging and resizing, **Add widget** picks from the registered widgets, and **Reset to default** restores the initial layout (while customizing, the title of a widget is the drag handle: it shows a grab cursor and its text cannot be selected, #430; the text in the widget body stays selectable). Below 1024 px the grid is a stack of one (below 40rem) or two columns in the saved order, and while customizing each widget has **Move up** and **Move down** instead of dragging. The layout is saved per user through `/api/layout` (with debouncing, and flushed when leaving the page). Widgets are registered in `dashboard/src/widgets/` with `registerWidget` (id, title, default size, component); a widget that crashes only breaks its own frame, an error outside the widgets shows an error screen with a reload button instead of a blank page, and a layout that refers to an unknown widget (for example from a removed plugin) shows a placeholder that can be removed.

**Look and shared pieces** (#91, then design system v3). The visual direction is the console of `docs/design-system/regulus-console-v3.html`: graphite surfaces, white for primary actions, violet for the mesh, Inter and JetBrains Mono (bundled, the hub's CSP allows no outside fonts). Colours are tokens on `:root` in `dashboard/src/styles.css` (the shell, the nodes and the node window are in `shell.css`). Status is always a badge with a word, never colour alone. Tables become one card per row below 48rem and their row actions move into an **Actions** menu (`RowActions` in `dashboard/src/ui.tsx`); destructive actions ask in place (`ConfirmButton`), not with the browser's `confirm`; **Copy** buttons say how to copy by hand where the browser cannot (a hub on plain HTTP has no clipboard API). The isometric room of the old "machine room" draft is not built.



The base installation ships these widgets, fed live by the hub (the dashboard follows `/api/stream` and reconnects by itself if the connection drops): **System** (host, OS, kernel, memory, load, uptime), **CPU** and **Memory** (current value plus a chart of the last 10 minutes, or the last hour with the range choice above it: the hour is read from the hub in averaged buckets), **Network** (received and sent rate, in total and per interface; the total leaves out bridges, container and VM ports, tunnels and VLANs, whose bytes are already counted on the physical interface, and the table still lists them all), **Disk usage** (one bar per mounted filesystem), **Uptime**, and **Servers**. The first five (without Uptime) are in the default layout. When several agents are connected, each widget has a selector and remembers the choice; by default it shows the hub's built-in agent.

The **Nodes** page (the **Servers** page before design system v3; the address is still `#/servers`) lists every enrolled server, online or not, in one of three views chosen with the icons at the right of the control bar (the choice is saved in the browser): **cards** (name, host name, state, type, last contact, and a pill when the software needs attention), a **compact list**, or the **map of the mesh** (the hub in the middle and every server linked to it, drawn on a canvas that pans with a drag and zooms with the wheel; the layout is computed, so any number of nodes fits without overlaps, see `topology.ts`). The control bar has the search (name, host, id or type; press `/` to jump to it), how many nodes are shown out of all, and a **Filter** popover (state, update available, node type). A node is shown with the logo of its **type** ([Design system v3](design-system.md)): the hub is the primary hub and every other server a generic node, unless the type was picked in the edit dialog, which for now is a look kept in this browser until the hub knows node types (#164). Users see each session as "Chrome 156 on Windows", and the Add a server form lets you choose how long the token is valid (15 minutes, 1 hour, 24 hours or 7 days). Each row, and the page of a server, shows its **role**: `hub` for the hub's own server and `agent` for every other one (#429; the word is in `docs/glossary.md`, in English and Italian, and an unknown role from a newer hub is shown as it is). A card, a row or a node of the map opens the **node window** (90 vw x 90 vh over the page, address `#/servers/<id>`, Escape or a click outside closes it): a header with the name, type, state, host name and last contact, a three-way switch **General** (the default), **SSH terminal** and **File editor** (the last two are placeholders: [node access](node-access.md) is designed, not built), the **pencil** (name shown in Regulus, kept on the hub for those with `servers.manage` and not for the hub's own server; node type) and close. General has the facts and the System, CPU, Memory, Network and Disk usage widgets bound to the server. Those with `inventory.read` also see a **Physical disks** panel there: each disk's identity key and kind, whether it is present, why it is not identifiable, a disk that another connected server reports too (a conflict, not a move), and the disks that moved to or from the server ([Disks](disks.md), #382). Those with `servers.manage` rename or revoke a server there and add new ones with **Add a server**: the title row of the Servers page carries the count by status ("2 online") and a **+** button at its far right that opens the Add a server panel; it is closed by default and a Close button or Escape closes it (#428). The command of a token stays on the page only while the token is pending: cancelling it removes the command at once, and when a server enrolls with it (the live stream sends `agent.connected`) the pending list is read again, the command goes and the panel says the token is no longer pending, without a reload (#426). The grant has no id, so the page tells its token in the pending list by name and end time. The two commands (install and agent) have an icon button to copy them, with an accessible name and a tooltip in English and Italian, so the command box keeps the whole row at any width; where the browser cannot copy (the clipboard API needs HTTPS or localhost, so a hub on plain HTTP cannot) a line under the command, in the warning colour, says to select the text and press Ctrl+C (#427). Its facts include when the server's certificate ends (#245; "not known yet" for an agent enrolled before the hub kept the date, until it next connects). Those with `servers.manage` see a banner on every page when the hub's CA or an agent's certificate ends within 90 days, with the way to renew it (`GET /api/certificates`). The page of a server that is stale, offline or revoked starts with a notice that gives its state and the time of the last contact the hub recorded, and says that what follows (name, version, certificate end, disks) is the last known; the live widgets are not drawn for a server that is not connected, so nothing looks alive, and no error page replaces it (#436). A revoked one cannot connect again; an agent that is too old or refused says why in the same place. The hub-side actions (rename, revoke) stay available; no action is sent to an agent from this page. A server whose agent cannot read part of the machine (a system without `/proc`, which uses the basic collector, or a file the agent cannot open) is marked **limited metrics** in the list, its page says what is missing, and each widget says "Not available on this server" for that part instead of showing zeros; a server that runs in a container shows the container in its facts and in the System widget, with a note on which figures follow the container's limits (#230, #325, [Supported platforms](remote-agents.md#supported-platforms)).

The **Plugins** page (`servers.read`) shows the state of the hub's plugins and of the plugins of each connected server that reports a plugins directory: id, version, state (starting, running, restarting, failed, incompatible, stopped, invalid) as a badge, restarts, since when, and the last error, with what a failed or incompatible state means. A directory that is not a usable plugin is listed too, as `invalid`, with its error. The page reads `GET /api/plugins` when it opens and again whenever the live stream says the plugins changed (`plugins.changed`), after a reconnection and when a server connects or disconnects; it does not poll. While the hub has no `plugins_dir` it says how to turn plugins on.
