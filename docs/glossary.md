# Glossary

What each word means in Regulus **today**. The names are provisional: the maintainer will decide the final nomenclature later (see [the naming plan](#naming-plan)). Until then, new text uses the words defined here, and nobody invents a new name without adding it to this page.

Status of a term: **in use** (the code or the UI uses it), **provisional** (used, but the name may change), **proposed in #103** or **proposed in #286** (only in the design issues of the epic for hub promotion and failover, or of the epic for managers and apps; no code yet), **deprecated**. For how the parts fit together see [architecture.md](architecture.md).

## Words with more than one meaning

These cause the most confusion. Say which one you mean.

| Word | Meaning 1 | Meaning 2 | Meaning 3 |
|---|---|---|---|
| **role** | *Node role*: what a Regulus process does on a machine, `hub` or `agent` (chosen by the subcommand `regulus hub` / `regulus agent`; installer option `--role`). Proposed in #104: more states such as redundant hub and pure-hub. | *User role*: a named set of permissions given to a person (`admin`, `operator`, `viewer`, custom ones). Code: `internal/auth`. | |
| **channel** | *Release channel*: `stable`, `beta` or `alpha`, chosen on the Updates page. Code: `internal/update`. | *Channel between hubs*: the secure link between the active and the redundant hub, proposed in #107. | *Out-of-band channel*: email, Telegram… to reach the administrator when the hubs cannot, proposed in #112. |
| **node** | Not used in the code, the UI or the current docs. Only the design issues of #103 use it, for "any machine in the group: agent, hub, candidate". | | |
| **hub** | The process (`regulus hub`). | The machine that runs it. | In #103: the *active* hub or a *redundant* hub; "the hub" then means the active one. |
| **server** | The UI word for a managed machine (**Servers** page, **Add a server**). | A *server certificate* or the *hub's HTTP server* in technical text. Not the same as the hub. | |
| **token** | *Enrollment token*: single-use, one hour, lets a new agent join. | *Setup token*: one-time, logged at first start, lets the first admin be created. | *Reset token* (password reset link) and the proposed *promotion token* (#105). Session tokens exist too but are never shown. |

## Terms

Alphabetical. "Closest other term" says what it is most often confused with.

| Term | Definition | Status | Where it appears | Closest other term | Italian UI label (proposed) |
|---|---|---|---|---|---|
| **access gateway** | A node with a public address that forwards the Regulus Access phone's connection to the active hub; mTLS stays end to end between phone and hub. Later it may also host notifications and, separately designed, authentication. | proposed in #152 | #161, [node-types.md](node-types.md) | *relay*, *hub* | gateway di accesso |
| **access root** | A directory listed on a node, `ro` or `rw`, beneath which the file browser may work; nothing outside it is visible. | proposed in #237 | [node-access.md](node-access.md) | *data dir* | radice |
| **active hub** | The one hub that currently orchestrates the group; exactly one per term. | proposed in #103 | #103, #104, #108 | *hub* (today there is only one) | hub attivo |
| **admin** | The built-in user role with every permission, including ones added later. | in use | `internal/auth/permissions.go`; **Users** page | *administrator* (a person) | amministratore |
| **agent** | A `regulus agent` process on a managed server. It reports the machine to a hub and runs the hub's commands. Remote agents connect outbound to the hub. | in use | `internal/agent`; `regulus agent`; `/api/agents` | *server* (the machine), *built-in agent* | agente |
| **agent id** | Identifier the hub gives an agent at enrollment; also the common name of its certificate. `local` is the built-in agent's id. | in use | `internal/fleet`, `proto` (`agent_id`) | *server name* (a display name set by an admin) | ID agente |
| **alert** | The record that a *condition* (a server offline, a disk fuller than a threshold, a certificate about to end) is true for one subject. States: `open`, `acknowledged`, `resolved`. Evaluated on the hub from data it already has. | proposed in #386 | [alerts.md](alerts.md) | *audit log*, *health check* | avviso |
| **allowed capabilities** (`allow`) | The list in the node's own `agent.yaml` of the capabilities that need consent (`relay`, `notifications`, `authentication`) and that the node agrees to run. Empty by default; set only on the node, as root; the hub can never change it. The node's half of the *two keys*. | proposed in #164 | [node-type-changes.md](node-type-changes.md) | *capability* (what the hub assigns) | funzionalità consentite |
| **API token** | A long random credential `rgt_…` that a user makes for a script, sent as `Authorization: Bearer`, stored only as a hash. It can do at most what its owner can, read-only by default, and never passes step-up. | in use (#406: API only; the Account page is still to do) | [authentication.md](authentication.md#api-tokens-388-406-storage-creation-and-the-bearer-check-the-account-page-and-a-test-are-not-done) | *enrollment token*, *session* | token API |
| **app** | Third-party software that runs **in containers** on a server, described by a declarative manifest (built on the Compose specification) and taken from a catalog, with its data in a declared volume. Not Regulus code and not a plugin. Example: Plex, Radarr, Sonarr, TriliumNext. Not *add-on* or *extension*. | proposed in #286 | #288, [managers-and-apps.md](managers-and-apps.md) | *plugin* (code that extends Regulus), *widget* | app |
| **assignment** | What the hub has decided a node runs: its preset plus per-node overrides, with a version number. Set by an administrator with `servers.assign`; sent to the node, which confirms. | proposed in #164 | [node-type-changes.md](node-type-changes.md) | *grant* (a delayed rule of the development node) | assegnazione |
| **audit log** | Record of security-relevant events (logins, user changes, enrollments, updates) in the database. | in use | `internal/auth`; **Users** page; `GET /api/audit` | application log (journald) | registro di controllo |
| **backend** | The real tool behind a *manager*: mdadm for RAID, ufw or firewalld or nftables for the firewall, Docker or Podman for containers, Tailscale for the VPN. One active backend per manager per server. Regulus uses it and does not write its own version. Not the *database backend* (SQLite or PostgreSQL). | proposed in #286 | #287, [managers-and-apps.md](managers-and-apps.md) | *database backend*, *plugin* | backend |
| **backup node** | A node that keeps the backups of the other nodes. Talks to the hub only and cannot contact other nodes. | proposed (idea only) | [node-types.md](node-types.md) | *redundant hub* (that one copies the hub's data to take over; a backup node stores backups) | nodo di backup |
| **backup (of the hub)** | One encrypted file with the database, `secret.key` and the CA of a hub, from which a hub is restored with its users and enrolled agents. Not the *backup node* (backups of other servers). | proposed in #253 | [backup.md](backup.md) | *backup node* | backup (dell'hub) |
| **built-in agent** | The agent that runs inside the hub process (agent id `local`) over the in-process transport, so the hub's own server is managed like the others. Setting `builtin_agent`. | in use | `internal/hub/hub.go`, `internal/inproc` | *remote agent* | agente integrato |
| **CA (certificate authority)** | The hub's own authority that signs agent certificates. Created at the first start in `<data_dir>/pki/`. | in use | `internal/pki` | a public CA (not used) | CA (autorità di certificazione) |
| **candidate** | An agent that asked to be promoted and waits, inactive, for the administrator's decision. | proposed in #103 | #104, #105 | *agent* | candidato |
| **capability** | A switch that says what a node of a given type is allowed and expected to do (for example `relay`, `notifications`, `backup-storage`). Proposed together with the role as "enum plus capability flags". Not used for the functions Regulus manages on a server: those are *managers* (#286). | proposed in #104 | #104, #160, [node-types.md](node-types.md) | *permission* (that is for users), *manager* | funzionalità (capability) |
| **certificate kind** | What a certificate issued by the hub CA is for, written in it as the URI `regulus:<kind>:<id>` (`regulus:agent:<id>`, `regulus:hub`; `device` reserved for Regulus Access). Each service accepts only its own kind. An agent certificate of a hub older than #316 has none and is still accepted as an agent (*legacy agent certificate*). | in use | `internal/pki/kind.go` | *role*, *capability* | tipo di certificato |
| **channel** | See the table above. Release channel: `stable`, `beta`, `alpha`. | in use | `internal/update`; **Updates** page | the channel between hubs | canale |
| **collector** | The part of the agent that reads the machine for a metrics report: `linux` (CPU, load, memory, disks, network and uptime from `/proc` and `statfs`) or `basic` (a system without `/proc`: time and uptime only). Each report names it. | in use | `internal/agent/collector.go`, `sysinfo.go`; `MetricsReport.collector`; [remote-agents.md](remote-agents.md#supported-platforms) | *plugin* | raccoglitore |
| **console** | The full-screen terminal interface, `regulus` or `regulus console`, with Status, Settings, Logs and Health tabs. Also called TUI. | in use | `internal/console`, `cmd/regulus/console.go` | *dashboard* | console |
| **contract** | A place where two pieces that may run different versions talk to each other (agent protocol, update contract, helper files, database schema, release layout, HTTP API, plugin API), each with its own version and rule of change. | in use | [versioning.md](versioning.md) | *module* (Regulus has one executable, not separate modules) | contratto |
| **contested disk** | A disk that two connected servers report at the same time (a cloned disk, an agent that lies, or a move that has not settled). It stays with the server that had it, is flagged on both servers' pages, and no move is written until one of them stops reporting it or goes away. | in use (#382) | [disks.md](disks.md); `disks.contested_by`; the **Physical disks** panel | *move* (a disk reported by another server after the first stopped), *duplicate* (two disks of one report with the same identifier) | disco in conflitto |
| **dashboard** | The web interface: widgets arranged per user. | in use | `dashboard/`, `internal/webui` | *console* | dashboard (pannello) |
| **data directory** | `data_dir`: where the hub keeps the SQLite database (with PostgreSQL only the keys, not the data), `secret.key`, `pki/`, the local socket and `hub.lock`, which one running hub holds so that a second one refuses to start (`/var/lib/regulus` with the package). Agents have their own (`/var/lib/regulus-agent`). | in use | `internal/config` | the configuration directory `/etc/regulus` | directory dei dati |
| **database backend** | Where the hub keeps its data: `sqlite` (a file in the data directory, the default) or `postgres` (a server the administrator prepared). Chosen by `database.type`. The password is read from the environment only. | in use | `internal/storage`; [database.md](database.md) | *data directory* | motore del database |
| **destination** | A remote address and port that a node's outbound traffic went to, with a name when known. Collected only when switched on for the node. | proposed in #283 | [network-visibility.md](network-visibility.md) | | destinazione |
| **development node** | A node for developer and AI tools with strongly limited reach: it talks to the hub only, never to other nodes, and uses shared resources only through delayed grants. | proposed in #168 | [node-types.md](node-types.md) | *compute node* | nodo di sviluppo |
| **disk identity key** | What identifies one physical disk and follows it between servers: its WWN, EUI-64 or NGUID, else its model plus serial number. Never a device name, a filesystem UUID or the hostname. A disk with no reliable identifier is not identifiable and is tracked per server and slot only. | in use (#148) | `internal/diskid`; [disks.md](disks.md); `GET /api/agents/{id}/disks` | *device name* (`sda`), *mount point* | chiave d'identità del disco |
| **enrollment** | The one-time act of an agent joining a hub: it proves a token, sends a certificate request and receives a client certificate. | in use | `internal/fleet`, `internal/agent/remote.go`, `EnrollmentService` | *connecting* (done on every start) | registrazione (enrollment) |
| **enrollment token** | A random, single-use token valid for one hour, made by a user with `servers.manage`; only its hash is stored. Listed and cancellable until used. | in use | `fleet.CreateToken`, `fleet.PendingTokens`, `fleet.RevokeToken`; `/api/enrollment-tokens`; **Add a server** | *setup token*, *reset token* | token di registrazione |
| **expected port** | A port declared by Regulus itself, a node type preset, an app manifest or a manager, or acknowledged by an administrator. Any other listener is *unexpected*. | proposed in #282 | [network-visibility.md](network-visibility.md) | *capability* | porta attesa |
| **explicit permission** | A user permission that a role with "every permission" (`admin`) does not get automatically; it must be given on purpose (node access). | proposed in #236 | `internal/auth` (planned) | *permission* | permesso esplicito |
| **exposure** | Where a listener listens: `loopback`, `lan`, `all` interfaces, `container bridge`, `vpn`. It is not reachability: a firewall can still block it. | proposed in #282 | [network-visibility.md](network-visibility.md) | *reachable* | esposizione |
| **failback** | Control returning to the old primary after a failover. What it means exactly is not settled. | proposed in #103 | #110 | *failover* | ripristino (failback) |
| **failover** | A redundant hub becoming the active hub because the active one is unreachable. | proposed in #103 | #108, #109 | *promotion* | passaggio al sistema di riserva (failover) |
| **fingerprint pinning** | An agent accepts a hub only if the hub's certificate chain contains a CA with a known SHA-256 fingerprint (`sha256:…`). | in use | `pki.PinnedClientTLS`; `--ca-fingerprint` | normal certificate validation (not used) | impronta della CA |
| **fleet** | Provisional name for the set of remote agents a hub manages, and for the Go package that keeps their tokens and registry. Not used in the UI. | provisional | `internal/fleet` | *group* (#103 text) | flotta |
| **grant** | A specific, written rule that lets a node use a shared resource (resource, direction, scope, expiry). Creating one needs an administrator's confirmation after a mandatory wait that the hub enforces. | proposed in #168 | [node-types.md](node-types.md) | *permission* | autorizzazione puntuale (grant) |
| **guided installation** | The "Add a node" wizard (and the same steps in the console and the CLI): choose a type, see what it needs, follow ordered steps that the hub checks one by one. | proposed in #165 | [node-type-changes.md](node-type-changes.md) | *enrollment* (one of its steps) | installazione guidata |
| **heartbeat** | A periodic message from the agent to the hub (15 s by default) that shows it is alive. | in use | `proto` `Heartbeat`; `internal/hub/agents.go` | *metrics* | heartbeat |
| **hub** | The Regulus process every agent talks to; serves the dashboard and the API. One per group today. | in use | `internal/hub`, `regulus hub` | *server* | hub |
| **keepalive** | HTTP/2 PING frames on the agent connection that tell a dead peer from a quiet one: the agent pings after 30 s without hearing from the hub and drops the connection after 10 s without an answer; the hub refuses pings closer than 15 s. Not a message of the protocol. | in use | `internal/protocol/keepalive.go`, `agent.ClientKeepalive`, `hub` `agentServerOptions` | *heartbeat* (a protocol message the hub reads) | keepalive |
| **link (traffic map)** | A line on the traffic map summarising the connections between two endpoints in an interval, with a kind, a state, a direction and a rate. Not a *channel*. | proposed in #283 | [network-visibility.md](network-visibility.md) | *channel* | collegamento |
| **limited metrics** | A server whose agent could not read part of the machine (`MetricsReport.unavailable` not empty, or the basic collector). The dashboard marks it and its widgets say "not available" for what is missing, instead of zeros. | in use | **Servers** page, widgets; `unavailable` in `/api/agents` | *offline*, *stale* | metriche limitate |
| **local** | The agent id of the built-in agent. | in use | `hub.BuiltinAgentID` | | locale |
| **manager** | A function of a server that Regulus manages, with one or more *backends* to choose from: RAID, firewall, containers, VPN, wake, storage, shares, backup, reverse proxy, UPS, system updates, scheduled jobs, virtual machines. The *system updates* manager is about the operating system's packages, not Regulus's own updates. | proposed in #286 | #287, [managers-and-apps.md](managers-and-apps.md) | *capability*, *plugin* | gestione (for example "gestione firewall") |
| **metrics endpoint** | `GET /metrics`: the hub's own figures and each connected server's latest in the Prometheus text format. | **mutual TLS (mTLS)** | Both sides present certificates: the hub's (checked by pinning) and the agent's (checked against the CA and the registry). | in use | `internal/pki` | | TLS reciproco (mTLS) |
| **node** | Not used today. In #103: any machine in the group. | proposed in #103 | #103 | *server*, *agent* | nodo |
| **node access** | The web terminal and the file browser of one node, as one feature: a session opened from the dashboard, carried by the agent's outbound connection, run by the session helper as a local account of the node. | proposed in #236/#237 | [node-access.md](node-access.md) | *Regulus Access* (the phone app: unrelated) | accesso al nodo |
| **node permission** | What a node may reach or use: the hub, shared resources, other nodes, the network around it. Defaults per node type, overridable per node. Different from a *user permission*, which is what a person may do on the hub. | proposed in #170 | [node-types.md](node-types.md) | *permission* (user), *capability* | permesso del nodo |
| **node type** | The kind of machine a node is: hub, redundant hub, compute node, backup node, access gateway, development node, AI node. Not to be confused with the *node role* of #104, which it refines. | proposed in #160 | [node-types.md](node-types.md) | *role* | tipo di nodo |
| **notification channel** | Where a message about an alert goes: the dashboard list (always), email (SMTP) or a signed webhook. | **open port** / **listener** | A TCP socket listening, or a UDP socket bound, on a server, with its address, exposure and owner. | proposed in #282 | [network-visibility.md](network-visibility.md) | *firewall rule* (whether it is reachable) | porta aperta |
| **operator**, **viewer** | Built-in user roles. `operator`: see and manage servers and arrange the dashboard. `viewer`: see servers and arrange the dashboard. | in use | `internal/auth/permissions.go` | | operatore, osservatore |
| **permission** | A named right, for example `servers.read`, `servers.manage`, `core.update`. Endpoints check permissions, not role names. | in use | `internal/auth` | *user role* | permesso |

The words *extension* and *add-on* are not used: they would be a second name for this. | in use (runtime on the agent and the hub; features not designed) | `internal/plugin`, [plugins/](plugins/README.md); #19 to #23 | *widget*, *app*, *manager* | plugin |
| **plugin API** | The version of the contract between Regulus and its plugins (`proto/regulus/plugin/v1` and the meaning of `plugin.yaml`): `api` in the manifest, `plugin.APIVersion` in the code. | **plugin manifest** | `plugin.yaml` at the top of a plugin directory: id, version, plugin API, the Regulus releases it needs, components and permissions. Read strictly. | in use | `internal/plugin/manifest.go`, [plugins/manifest.md](plugins/manifest.md) | | manifesto del plugin |

| **promotion** | Turning an agent into a hub (or a redundant hub), requested on the candidate and approved on the active hub with a token. | proposed in #103 | #105 | *failover* | promozione |
| **protocol version** | The version of the agent–hub contract (`protocol.Version`), negotiated when an agent connects. Separate from the release version. | in use | `internal/protocol` | *release version* | versione del protocollo |
| **pure-hub** | A hub that orchestrates and hosts no workloads, for small machines. Probably "hub with the built-in agent off" plus a rule; not confirmed. | proposed in #103 | #104, #111 | *hub only* setup | hub puro |

### Server states shown in the UI

`connected` (online), `stale` (silent for two heartbeats), `offline`, `revoked`, and `incompatible` (refused because of its version). Source: `dashboard/src/api.ts` (the `status` field) and `dashboard/src/AgentList.tsx`.

## Naming plan

- **Who decides.** The maintainer decides the final nomenclature, later, and it is explained in this file.
- **Meanwhile.** New text (issues, pull requests, documents, comments) uses the terms above. If you need a word that is not here, add it here in the same pull request, with a status and a source. Do not use "node" in code or UI; keep it for the design discussion of #103 until it is decided.
- **When the names are decided**, one follow-up issue renames them everywhere. The list to cover: documents (README, `docs/`, this glossary), Go identifiers and package names (for example `fleet`, `BuiltinAgentID`), command-line subcommands and flags, the HTTP API paths and JSON fields (a breaking change: needs a version note), the Protobuf messages (a protocol change: needs the version rules), configuration keys, the dashboard and console strings **in English and Italian** (`dashboard/src`, `internal/console/strings.go`, and the translation mechanism of #125), the installer options, systemd unit names, and the titles and labels of issues.
- **What must not be renamed lightly:** anything a deployed hub or agent already uses on disk or on the wire (file names, table names, protocol field names, unit names), because an installed agent of the previous release must keep working (the N / N-1 rule).

## Italian UI labels

This is the only place in the documentation that has Italian. The GUI supports English and Italian (#120): the texts live in the catalogs `dashboard/src/i18n/messages/<area>.{en,it}.ts` and in the console tables `internal/console/strings.go` and `strings_it.go` (#125, #191). The right-hand column above is the reference those translations should follow; the Italian is a draft the maintainer has not reviewed yet. Where a term is a technical word that Italian users also say in English (hub, plugin, widget, dashboard), the label stays in English.
